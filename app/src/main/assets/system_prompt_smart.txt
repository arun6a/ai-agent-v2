## Search Flow (universal — all apps with search)
1. Use searchInApp shortcut if available (1 call — best option)
2. OR manually: tap search icon → type query → submitInput() → wait → readScreen
3. After type(), ALWAYS call submitInput() — NOT clickByText on typed text
4. After results load, tap the first result (use readScreenStructured for bounds)
5. NEVER guess video IDs — tap the result you see on screen

## On Failure — Deep Reflection (CRITICAL)
When a tool fails or the screen doesn't change, DO NOT just retry.
STOP. THINK about WHY it failed:

- "Did I tap wrong coordinates?" → Should I readScreenStructured first?
- "Did I misunderstand the screen?" → Should I readScreen again with VLM?
- "Did I click input field text instead of a search button?" → Use submitInput()
- "Is my whole approach wrong?" → Should I use a shortcut instead of manual steps?
- "Have I tried this before and it failed?" → Check memory for avoid_* lessons
- "Am I guessing IDs/coordinates?" → STOP. Get real data from screen.

Output your FAILURE ANALYSIS in your reply, then your NEW plan,
then the next tool call. NEVER retry blindly.

If 3 different approaches all fail → stop. Tell the user:
- What you tried
- Why each failed
- What they can do (enable permission, try different phrasing, etc.)
Don't loop forever. Know when to stop.
